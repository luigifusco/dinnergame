# Sideplot

**Small talk. Secret plans.**

A secret layer of playful missions and running jokes underneath an ordinary
dinner or evening at a bar. Everyone knows a game is happening; nobody knows
what the others are trying to do.

See [GAME_DESIGN.md](GAME_DESIGN.md) for the rules and game formats.

## Print without installing anything

The [print directory](print) contains ready-to-print PDFs generated from the
included deck:

| File | Purpose |
|---|---|
| `sideplot-duplex.pdf` | Automatic double-sided printing: front 1, back 1, front 2, back 2. |
| `sideplot-fronts.pdf` | Front sheets only, for manual double-sided printing. |
| `sideplot-backs.pdf` | Matching back sheets in the same sheet order as the fronts. |

The library contains **68 cards: 22 running bits and 46 missions**, across eleven
internal themes. The complete deck uses five A4 sheets, or 10 duplex PDF pages.
For the three-card format, provide at least one running bit and two missions per
player, plus spare missions for replacements.

Some missions use paper, a pen, or napkins. Exchange a mission if its props
aren't available.

Questions, hints, and demonstrations can help complete missions when they have a
conversational pretext; simply requesting the listed action does not count.
See the [difficulty guide](GAME_DESIGN.md#mission-difficulty) for examples and
playtest guidelines. Difficulty bands are provisional authoring notes, not
extra YAML fields or printed labels.

## Print specification

| Setting | Value |
|---|---|
| Paper | A4, portrait |
| Card orientation | Landscape |
| Trimmed card size | 88 x 31.5 mm, before lamination |
| Layout | Two columns by eight rows: sixteen cards per sheet |
| Gutters | 5 mm between columns; 2.5 mm between rows |
| Duplex setting | Flip on the long edge |
| Scaling | Actual size / 100%, not "fit to page" |

Fronts have 5 mm horizontal and 2.5 mm vertical text insets, with the title and
type label sharing a header row. Back artwork is inset 2 mm from the cut edge,
allowing a small amount of printer registration drift without cutting into the
design. Crop marks indicate the full 88 x 31.5 mm card, not the inset background.

Running bits have **sage-green looping paths**; missions have **amber angular
paths**. Each back has a darker central band and two lighter bands, without a
badge, border, or text. The curved and angular patterns distinguish the types
even when printed in grayscale.
Cards are unbranded: fronts show only the type, title, and task; backs are
wordless. There are no slogans, serial numbers, or repeated rule reminders.

All artwork is original vector geometry generated by the script. It stays sharp
in the PDF and needs no image assets, browser, or external design software.

The playful, handwritten-style **Balsamiq Sans** font is bundled in regular and
bold weights under `assets\fonts`. Fonts are embedded wherever used in the PDFs;
no system font installation or network connection is needed to generate or print
the cards.
The unmodified fonts come from [Google Fonts](https://github.com/google/fonts/tree/main/ofl/balsamiqsans)
and are distributed under the SIL Open Font License 1.1; the copyright notice
and license are included in `assets\fonts\OFL.txt`.

### Printing and laminating

1. Print only pages 1-2 of `sideplot-duplex.pdf` as a trial. Select A4 portrait,
   actual size / 100%, double-sided, flip on the long edge. Disable booklet
   printing and any additional pages-per-sheet setting.
2. Measure the 50 mm scale on the sheet. Hold the sheet against a light to check
   front/back registration. Printer feed tolerances can still cause small shifts.
3. Print the remaining sheets on opaque paper or card stock supported by your
   printer. Thin, translucent paper can expose the secret text through the back.
4. Cut the printed cards along the crop marks **before laminating**.
5. Arrange the cut cards in laminating pouches, leaving enough space around each
   card for a sealed border. Follow the pouch and laminator instructions.
6. Laminate, then cut out each card again, leaving the manufacturer's recommended
   clear sealed border, typically 2-3 mm on every side. The finished laminated
   cards will therefore be larger than 88 x 31.5 mm.

Do not laminate an uncut sheet and then cut flush to the card edges: that removes
the sealed border. If rounding corners, preserve the clear seal around the card.
Shuffle running bits and missions separately after cutting; the authoring themes
are not intended to determine the hands people receive.

For manual double-sided printing, use the separate front and back PDFs. Test one
sheet first to establish your printer's refeed orientation. Both PDFs use the
same sheet order; a particular printer tray may require reversing the order of
back **pages**. Do not mirror the artwork or reverse the card positions yourself:
the generator already aligns them.

## Edit the cards

The [cards directory](cards) is the source of truth for the printable deck.
Running bits and missions are separate, with smaller files grouped by what the
card asks a player to do. Themes are internal authoring notes, not printed labels
or additional game rules. [GAME_DESIGN.md](GAME_DESIGN.md) explains the families.

```text
cards\
  deck.yaml
  running\
    callbacks-and-fiction.yaml
    language.yaml
    perspectives.yaml
    social-habits.yaml
  mission\
    callbacks-and-adoption.yaml
    corrections-and-reactions.yaml
    props-and-surprises.yaml
    say-something.yaml
    shared-decisions.yaml
    small-actions.yaml
    stories-and-know-how.yaml
```

`cards\deck.yaml` contains only the deck name used in PDF metadata:

```yaml
name: Sideplot
```

Every other YAML file contains one card type and an optional internal theme:

```yaml
type: mission
theme: Getting someone else to say a particular word
cards:
  - id: mission-shortcut
    title: The Scenic Detour
    text: >-
      Get another player to say "shortcut" while discussing a task or journey.
      Don't say it yourself, ask for the word, or start a guessing game.
    copies: 1
```

| Field | Meaning |
|---|---|
| `name` | Only in `deck.yaml`: single-line PDF metadata, never printed on cards. |
| `type` | At the top of each card file: exactly `running` or `mission`, applying to every entry. |
| `theme` | Optional file-level authoring note. Never printed or used to change the rules. |
| `id` | Unique across the entire library, using lowercase letters, digits and single hyphens. |
| `title` | Short title printed on the front. |
| `text` | Plain-text task. Use `>-` to fold wrapped YAML lines into a paragraph, or `|-` to preserve line breaks. |
| `copies` | Optional positive integer; defaults to one. Copies stay together in file order. |

All `.yaml` and `.yml` files beneath the library directory are discovered
recursively, except its root `deck.yaml`. Add a file or split a theme into nested
files such as `cards\mission\say-something\words.yaml` and
`cards\mission\say-something\phrases.yaml`; no Python changes or file list are
needed. Each new file gets its own `type`, optional `theme`, and non-empty `cards`
list. Move entries rather than copying them: duplicate IDs are an error.

Folder names are organizational; the file-level `type` determines the card back.
Entries do not repeat or override `type`. Running bits print first, then missions.
Within each type, files sort by relative path, and entries retain their YAML list
order. Theme labels never appear in the PDF, including on the backs.

Remove an entry or file to omit it, or use `--kind` to print just one type.
Non-YAML files are ignored. Put punctuation-rich text under `>-` as shown rather
than trying to escape it on a single YAML line.

Text is treated literally, not as HTML or Markdown. The deck accepts English and
Western European characters, including accented Italian text. Unsupported
characters, such as emoji or other writing systems, produce
an explicit error instead of missing-glyph boxes.

Titles and body text wrap automatically. The generator reduces body text only as
far as 9 pt; if a card still does not fit, it reports that card's ID and asks you
to shorten it. Unknown fields, duplicate IDs across files, duplicate YAML keys,
empty card files, and invalid copy counts are errors. Input errors identify the
source file.

## Generate the PDFs

Use Python 3.10 or newer. From this directory in PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts\generate_cards.py
```

This regenerates all three PDFs in `print`. Generated PDFs are tracked in Git so
the deck can be downloaded and printed without setting up Python. Regenerate
them whenever you change anything under `cards` or the rendering code.

Useful options:

```powershell
# Check definitions and text fit without writing files.
.\.venv\Scripts\python.exe scripts\generate_cards.py --check

# Print only missions into a separate directory.
.\.venv\Scripts\python.exe scripts\generate_cards.py --kind mission --output print\missions

# Read a different library directory (which must contain deck.yaml).
.\.venv\Scripts\python.exe scripts\generate_cards.py --cards my-card-library

# Read a legacy single-file deck.
.\.venv\Scripts\python.exe scripts\generate_cards.py --cards my-cards.yaml

# For a printer configured to flip on the short edge.
.\.venv\Scripts\python.exe scripts\generate_cards.py --flip short-edge --output print\short-edge
```

A legacy single-file deck still uses `name` and `cards` at the top level, with
`type` on each card. This is distinct from the theme-file format above; pass the
library directory, not an individual theme file, when using the split format.

Long-edge backs mirror the columns; short-edge backs mirror the rows. Text itself
is never mirrored. Empty positions on a partial final sheet remain correctly
paired. The default checked-in PDFs use long-edge printing.

Input validation and text fitting happen before output is written. All three
PDFs are rendered to temporary files before replacing the previous set. PDF
metadata is deterministic, so unchanged inputs do not produce timestamp-only
changes.

## Development

The renderer and vector back designs are in `scripts\generate_cards.py`.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

The tests cover recursive discovery, shared file types, internal-only themes,
cross-file validation, and legacy decks. They also inspect real PDFs for
uncluttered card text, embedded fonts, type-specific backs, duplex page order,
partial-sheet alignment, literal text handling, and reproducible output.
